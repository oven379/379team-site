# Исправления на действующем сервере

Правки nginx.conf в GitHub не заменяют конфигурацию Ubuntu nginx в /etc/nginx.
До правок сохраните резервную копию действующего файла сайта, включая настройки сертификатов.

1. В действующий server для itcompania.ru перенесите location-правила из nginx-site-fixes.conf.example. Не создавайте второй location /: замените существующий fallback /index.html на =404.
2. Выполните nginx -t. Только при успешной проверке: systemctl reload nginx.
3. Выпустите сертификат с обоими именами itcompania.ru и www.itcompania.ru вашим действующим способом. До этого HTTPS-редирект с www не исправит ошибку сертификата.
4. На www настройте return 301 https://itcompania.ru$request_uri; сохранив настройки SSL и ACME.
5. Проверьте: главная 200; случайный адрес 404; /.git/HEAD и /_tools/blog/posts_plan.py — 404; www — 301 на основной домен с валидным сертификатом.

## Обновление карты сайта
Перед коммитом: python3 _tools/build_site.py. Добавляйте в sitemap только вышедшие статьи. Таймер в браузере не обновляет XML на сервере. При ручной выкладке нужна повторная сборка и выгрузка после наступления дат публикации. Это не требует изменения самих дат статей.
